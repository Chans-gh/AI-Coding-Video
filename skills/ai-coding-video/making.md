# 出样片与做风格包

[← 返回 SKILL](SKILL.md)

讲 1 级（样片）和 2 级（风格包）具体怎么做，以及完整出片的[整片](#整片)规矩。提示词怎么写看 [prompting.md](prompting.md)，配声音看 [sound.md](sound.md)。下面提到的代码都随本 Skill 一起安装：`samples/`（出片工具和每个已验证风格的样片代码）、`packs/`（风格包），不用联网取。

## 动手之前

1. **确认技术路径在用户项目里跑得通**：要浏览器（Canvas 2D、WebGL、SVG）就确认有 Chromium 或 Playwright；要 GPU 就确认 WebGL2 能开；要配声音就确认有 Python 和 numpy、scipy；出视频要 ffmpeg。缺什么先说，不要写到一半才发现。
2. **优先改现成代码**：条目有「样片代码」的，从 `samples/<编号>/` 改，比只拿提示词重写稳定得多；有「风格包」的，直接用 `packs/<名字>/`。只有「技术（建议）」的条目没人验证过，要向用户说明效果靠试。
3. **用用户的真东西**：品牌色、字体、产品名、真实的一句文案。用占位文字做出来的样片，用户很难判断合不合适。

## 1 级：样片

目标是 3–5 秒、横竖两版，让用户判断「这个风格放在我的项目里像不像样」。

### 自带的出片工具

用户项目已经有 Remotion、Motion Canvas 这类管线的，用它自己的，样片代码只当画法参考。没有的，用本 Skill 自带的这套：

```bash
cp -R <本 Skill 目录>/samples ./video     # 拷进用户项目再改，不要直接改 Skill 安装目录（更新 Skill 会覆盖）
cd video && npm install                  # 字体和绘图库装进 node_modules/，出片时从本地载入，不联网
export AICV_SKILL=<本 Skill 目录>          # new.py 从这里读风格条目
python3 batch.py C-013 --quick           # 先原样跑通一个样片，确认环境没问题
python3 new.py C-013                     # 或：给还没有样片的风格起骨架（已有的文件不覆盖）
```

要 Node.js 18 以上、Python 3（Playwright 并装好 Chromium、Pillow、numpy、scipy）和 ffmpeg；浏览器可用环境变量 `CHROME` 指定。函数速查见 [samples/API.md](samples/API.md)，`batch.py` 的用法写在它文件开头。T 类、G 类样片只带了代码和 `assets.json`（素材清单），素材本身不随 Skill 安装（风格包 `packs/` 的演示素材除外，随包一起装）：T 类可以照 `assets.json` 用 `tools/assets.py` 重新下载，G 类要用户按 [materials.md「配置生成服务」](materials.md#配置生成服务) 配好服务再生成，或换成自己的素材。

**改的顺序**（照这个来，比从零设计稳）：

1. 拷对应风格的 `samples/<编号>/`，原样跑通 `--quick`（画面和声音都过）。
2. 换内容：题材、主体、文字、品牌色、时长，一次只改一处，每改一处跑一次 `--quick`。
3. 声音单独试：`python3 batch.py <编号> --sound`，别等画面全做完才第一次跑。
4. 画面都对了，再加细节。**细调最多 3 轮**（一轮 = 改一处、跑一次 `--quick` 看截图）：3 轮后不管满不满意，先去掉 `--quick` 出完整的横竖两版交给用户，把还想改的地方列出来，由用户决定要不要再调。不要停在半成品。

**哪些照用、哪些自己来**：

| 层 | 内容 | 怎么对待 |
|---|---|---|
| 管线 | `lib/lib.js`、`lib/synth.py`、`batch.py`、`render.py`、`player.html`；完整出片另有 `tools/voice.py`、`tools/film.py` | 照用，不要重写；时间驱动、截帧、合成声音、自检都在里面 |
| 画法 | 样片里怎么做出这种风格：镂空、光照、纹理、笔触、分层、运动方式 | 可以借，按用户的主体重新组合 |
| 内容 | 样片里的角色、场景、构图、配色、文字、配乐旋律 | 换成用户自己的；样片只是示范，主体和构图不能和样片一样 |

### 写法

- **每帧只由时间 t 决定**：画面写成 `draw(t)`，不依赖上一帧的状态，不用 `Math.random()`，随机数用带种子的发生器。这样可以任意跳帧检查，逐帧导出也不会掉帧、错位。
- **横竖两版分别构图**：竖版不是横版裁出来的。主体在横版里左右排，到竖版里通常改成上下排；字号、留白按短边缩放。
- **先定节拍**：入场、强调、收尾落在拍点上，声音也按同一个拍子放。本库样片用 160 BPM（一拍 0.375 秒，3 秒正好 8 拍）。
- **标志元素要画出来**：提示词里写的 3–5 个标志元素每个都要在画面里认得出，禁止项一条都不能出现。
- **文字**：中文要折行（标点不放行首），字体等加载完再画第一帧，长句在竖版里会不会挤出画面要单独看。

参考写法：[样片骨架和 API](samples/API.md) · [一个完整样片（C-044）](samples/C-044/) · [合成器 synth.py](samples/lib/synth.py)

### 出片和自检

逐帧截图再用 ffmpeg 合成视频，是最不挑环境的办法；用户项目已经有 Remotion、Motion Canvas 这类管线的，就用它自己的。交给用户之前自己先查一遍：

- 先看数字：时长、帧数、文件大小、首帧和末帧是不是全黑或全白。
- 再看抽帧拼图：每隔半秒到一秒取一帧拼成一张图，一眼看出节奏和构图。
- 只有可疑的那几帧才单独放大看：文字出界、元素重叠、竖版挤压、字体没加载成方块。
- 和风格的缩略图 `images/<编号>.jpg` 并排看：标志元素认不认得出；主体不该被做成虚的、糊的（只有提示词要求的地方才虚化）。
- 和样片 `samples/<编号>/` 的画面比：主体、构图要是用户自己的，不能只是换了颜色的样片。

### 交付

- **用户还没定风格**：一次给 2–3 个候选，每个给横屏 16:9 和竖屏 9:16 各一段视频、一张抽帧拼图，附一句「为什么选它」，让用户挑。
- **用户已点名选定 1 个样式**：直接只做这 1 个，不必硬凑 2–3 个候选。如果这个样式下有几个分化方向拿不准，可在 1 级用 2–3 张关键静帧或 3 秒单镜头轻对比，锁死 1 个方向再进 2 级。
- **用户选了多个样式准备混搭做一支片子**：不必为每个样式分别做风格包，直接走完整出片（[film.md](film.md)），用 `unify` 统一全片，靠第 5 步典型样片验证。

用户点头之前不要往下做 2 级。

## 2 级：风格包

风格包是把通过的风格做成可反复用的代码模块和风格说明，让以后这个项目的视频换内容不换风格。本库有三个**官方满配范例**：[dark-keynote 暗色科技发布会](packs/dark-keynote/)（C 类，切品牌色）、[news-brief 新闻资讯解说](packs/news-brief/)（T 类，切画面组织）、[style-swap 分镜换画风](packs/style-swap/)（G 类，切画风），用来示范「改一个参数就能换整套」，下面的做法都能在它们里面找到对应代码。

**两条路径都支持**：

- **先出包，再出片**：想在正式做整片前，先看选中样式套上自己分化方向、品牌色和内容后的轻量演示片来拍板 → 先定 **1 个**分化方向，建**轻量起步包**（1 套配置、最小骨架 + 4–8 个核心部件、10–25 秒轻验证片），点头后再做整片、边做边按需补部件。
- **先出片，后抽包**：只做单支片子、多样式混搭，或还没定是否长期做系列 → 直接先走完整出片（[film.md](film.md)），用 `unify` 统住全片，靠第 5 步典型样片验收；确认要长期做系列后，再把跑通验收的镜头抽进风格包。

**多样式混搭原则（不重复造大包）**：

- 单支混搭片子优先**无包混搭**：`unify.pack` 写 `null`，全片靠 `unify`（色板、字体、字幕、转场、配乐、音色）统一，各段各自引用选中的样式编号（如 `C-036`、`T-007`）。
- 长期系列若局部混搭，只维护 **1 个主风格包**（管全片统一层和高频部件）；客串样式的段或分镜直接写 `ref: "C-xxx"`，沿用主包的色板/字体/字幕外壳、按本片实际镜头单写，**绝不为客串样式再建一套几十个部件的完整风格包**。

### 样式分化与切换维度（先定 1 个方向，默认只出 1 套）

同一种样式样片，落到具体项目里往往会沿不同维度分化。代码里把可切维度写成单参数，以后改一个参数就能换一套；但在**什么时候出几套**上要严格省算力：

| 类别 | 常见分化与切换维度 | `meta.json` 写法与代码口子 | 官方范例 |
|---|---|---|---|
| **C 类**（纯代码） | 1. **主题色与明暗极性**（如紫/橙/绿、暗底科技 vs 浅底纸面） | 写 `accents`：`[键, 中文, 英文, 色值]`，播放器参数 `accent`，主题函数只收这一个色推全套配色 | [dark-keynote](packs/dark-keynote/) |
| **C 类**（纯代码） | 2. **材质/线型与信息密度**（如手绘纸纹 vs 纯净矢量、极简粗块 vs 精密细线、大留白 vs 高密仪表盘） | 写 `switch` + `variants`，播放器参数 `v`，用 `Q.get('v')` 切一套材质或密度配置 | — |
| **T 类**（真实素材） | 1. **画面组织方式**（单图推拉 / 2.5D 视差分层 / 多图拼贴分屏） | 写 `switch` + `variants`（`v`）。每种组织写一个 `draw()` 对象画照片，并返回文字卡与标注坐标，多种组织共用同一套部件 | [news-brief](packs/news-brief/) |
| **T 类**（真实素材） | 2. **调色与素材包装框**（原色满屏沉浸 / 档案复古滤镜 / 杂志留白卡片或画中画） | 写 `switch` + `variants`（`v`），切换滤镜与框体参数 | — |
| **G 类**（AI 生成素材） | 1. **画风**（写实摄影 / 水彩插画 / 3D 黏土 / 赛博霓虹等） | 写 `switch` + `variants`（`v`）。提示词拆成「镜头段 + 风格段 + 约束段」写进数据文件，**只换风格段**，脚本拼完整提示词写进 `assets.json` 生成；画风一换整套出图，剪辑代码不动 | [style-swap](packs/style-swap/) |
| **G 类**（AI 生成素材） | 2. **动态方式与镜头形态**（静态生图代码推拉 vs 首尾帧生视频运镜；满屏沉浸 vs 分镜卡） | 写 `switch` + `variants`（`v`），切换镜头组织与素材生成方式 | — |

**定方向与出套数的四条规矩**：

1. **先用文字 + 三档可改边界定方向，不直接渲 3 套包**：选定样式样片后，按上表找出该样式最核心的 **1 个可分化维度**，再用下面「三档可改红绿灯」和「口语翻译表」定出具体调整项（每轮最多改 **5 项**，记进 `CHANGES.md`），让用户拍板选 **1 个**方向（用户已自带明确品牌色或画风的直接跳过）。若文字还拿不准，**先用真实代码只渲 1 帧做左右对比**（`python3 batch.py pack:<包名> --vs <原样片编号> --ar 16x9`，左原样片、右改后；最多调 2 轮），**严禁直接渲染 3 套完整风格包让用户选**。
2. **代码留切换口子，渲染默认只出 1 套**：`pack.js` 里仍按单参数（`accent` 或 `v`）写好切换结构，方便日后改一个参数就能换色、换组织或换画风；但用户项目的 `meta.json` 默认只填选定的那 **1 套**，只出 **1 支**演示片，不出 15 秒切换对比片段。
3. **何时才配 3 套切换 + 切换片段**：只有两种情况才在 `meta.json` 配多种切换并各出一支——① 用户明确要求同时出多套配色/画风做切换对比；② 维护本仓库官方展示范例包。日后要**加第 2 / 第 4 种切换**：在 `accents` 或 `variants` 加一行；T 类再写一个画面组织对象，G 类在数据文件里加一行风格段、补生成这一套图，具体步骤写进包的 `STYLE.md`。
4. **素材随包走**：T、G 类包的 `demo/assets/` 随 Skill 一起安装（体积见「演示片」），用户拷出去不用重新下载、不用配生成服务就能先跑通演示片；换成自己的素材时照 `assets.json` 记出处、许可或提示词。

**三档可改红绿灯（所有 264 种样式通用）**：

| 档位 | 能改什么 | 怎么对待 |
|---|---|---|
| 🟢 **安全可改** | 不破明暗逻辑的配色（`accent`）、字体（须覆盖成片语言）、运动快慢与节拍、声音配器、局部动效 | 改完仍是同一个风格；每次给 2–3 个具体方向让用户选 1 个 |
| 🟡 **会改气质** | 材质与渲染质感、色彩极性本身（暗底改浅底）、镜头运动语法、T 类画面组织 / G 类画风 | 可以改，但先向用户说明改后会失去原样片的什么味道 |
| 🔴 **不可改** | 样式的本质（核心画法）和底层渲染路线 | 改了就是另一种风格；直接回库里建议更接近的基础样片，不硬改 |

**模糊口语 → 具体改动翻译表**（用户说不出专业维度时，直接按这张表落成可核对的改动并记进 `CHANGES.md`）：

| 用户口语 | 通常对应改这几项 |
|---|---|
| 更高级、更克制 | 减少用色、拉大明暗对比、放慢入场缓动、增大留白、字重变细 |
| 更活泼、年轻、节奏快 | 更亮的强调色、踩拍硬切、带回弹缓动（`eOutBack`）、加轻打击乐 |
| 更安静、沉浸、适合讲解 | 降慢节拍与运动幅度、延长文本停留、弱化粒子与装饰、稀疏长音铺底 |
| 像我们品牌 | 品牌色优先当强调色（不直接铺满背景）、标题换品牌字体、头尾加品牌标志与角标 |
| 更复古、有档案质感 | 纸纹/噪点叠加、微暖或微冷旧色偏、打字机/等宽字标、出处角标 |

### 两档规模：轻量起步 vs 完整满配

| 维度 | 轻量风格包（项目起步默认） | 完整风格包（长期系列 / 官方满配范例） |
|---|---|---|
| **什么时候做** | 选定样式后想先看轻演示片拍板，或首片完成后沉淀成包 | 固定栏目反复高频出片，或制作本仓库对外展示范例 |
| **切换套数** | **1 套**（用户选定的 1 个方向；代码留切换参数口子） | 用户项目通常 1 套（需要对比时可多套）；官方范例 3 套 |
| **部件与层规模** | **最小骨架 + 4–8 个核心部件**（仅覆盖本片/本期高频镜头） | 参照 `dark-keynote`：**整屏 ≥30 种、叠加 ≥5 种、层 7 个**（题材窄的在 `STYLE.md` 写明理由） |
| **演示片** | 10–25 秒轻量验证片（`meta.json` 不写 `full`）；先出片后抽包时直接用首片典型样片验收、可不出独立演示片 | 20–90 秒完整分镜合集（`meta.json` 写 `full`）；可选 15 秒切换片段 `clip.js` |
| **`lookup.json`** | 可选（缺时 `plan5.py` 只提醒不报错），或先只写已有部件、其余主角用 `instead` 回退 | 必填，15 种主角和 `sizes` / `motion` 完整覆盖 |

**边做片边按需生长，防弱模型翻车的 4 条护栏**：

1. **一键脚手架起步，不从零硬写框架**：在 `video/` 下用自带脚手架 `python3 new_pack.py <包名> --from <样片编号> --accent '#2BD99F'`（T/G 类可加 `--switch 画面组织 --variant single`）直接生成 1 套配置的最小骨架（4 个核心部件 + 4 个基础层 + 12 秒演示片 + `STYLE.md` + `CHANGES.md`），比手写几十个文件稳得多；特殊画法再从官方 3 个范例包或 `samples/<编号>/` 拷来改。
2. **先验单帧，再验最小骨架**：先跑 `python3 batch.py pack:<包名> --vs <原样片编号> --ar 16x9` 出「原样片（左） vs 改后（右）」单帧左右对比图给用户拍板（最多调 2 轮）；拍板后立刻跑 `python3 batch.py pack:<包名> --quick --ar 16x9` 把最小骨架和声音跑通。
3. **一次只加 1–2 个部件并立刻 `--quick` 看抽帧**：写一个验一个，抽帧通过再写下一个；**严禁一口气写几十个部件再总调**（上下文一长，弱模型极易语法报错、坐标错位或画面退化）。
4. **按需扩充**：轻量包通过后就去出片；后续每做一期新片遇到新镜头需求，再对照「完整部件能力目录」往包里追加 1–2 个真实用到的部件，自然长成完整包。

### 包里有什么

| 文件 | 是什么 |
|---|---|
| `pack.js` | 主题和部件 |
| `sound_kit.py` | 每种部件出现时放什么音，外加一段铺底 |
| `STYLE.md` | 风格说明：分化方向、调色板、字体、版式、运动、声音、禁止项 |
| `CHANGES.md` | 相对原样片的改动记录（维度、原样片、现在、原因，每轮 ≤5 项；轻量起步包可选，建议保留） |
| `README.md` | 部件表：每个部件的调用方式和内容字段 |
| `meta.json` | 名字、部件清单 `parts`（`[中文名, 英文名, "seg" 或 "layer"]`，标明整屏部件还是层；叠加部件也记 `"seg"`，名字后加「（叠加）」）、切换配置（`accents` 品牌色，或 `variants` 加 `switch` 切换别的维度；第一种是默认——**用户轻量包默认只写选定的 1 项**）、`full`（完整演示片的画幅；**轻量 10–25 秒验证片不写此项**，免得触发 20–90 秒时长告警）、`clip`（切换片段的画幅，写了就和 `full` 相同、只出这一种画幅；不写时切换片段出在另一画幅） |
| `lookup.json` | 样式查表：主角 → 部件、字号三档、动效，接策划（格式 5）时照它定样式，见下面「样式查表」（**官方包必填；用户轻量起步包可选**，可随部件扩充再补） |
| `demo/` | `segments.json` 分镜表；`scene.js`、`sound.py` 演示片（先出包时必需；先出片后抽包时可直接用首片典型样片验收）；`clip.js`、`clip_sound.py` 15 秒切换片段（可选，只做多套切换对比时出，画幅跟随主演示片）；T、G 类的包另有 `assets/` 和 `assets.json`（素材随 Skill 安装，拷出去就能出片） |

### 演示片

- **轻量验证演示片**（先出包时用）：只按用户选定的 **1 套**配置出一支 10–25 秒的短演示片，把已做的 4–8 个核心部件串起来看配色、字号、安全区与节奏（若走「先出片后抽包」，直接用首片典型样片验收即可，不必另做演示片）。
- **完整演示片**（满配包 / 官方范例用）：一支「分镜合集」，让人一眼看出包里有多少种不同的呈现。它不分段，一行就是一个分镜（镜头）。按真实节目排：开场 3–4 个镜头 → 4–5 章（每章一张章节闪卡加 6–8 个镜头）→ 片尾。**每种分镜只出现一次**（章节闪卡除外），相邻镜头不用同一类，不靠把一个镜头拉长来凑时长。时长由分镜数定，20–90 秒（`dark-keynote` 45 种约 71 秒）。
- **镜头短、切在拍上**：一个镜头 1.5–2.25 秒，章节闪卡 0.75 秒，片尾约 3 秒；每个镜头的时长都是整拍（`scene.js` 启动时检查）。镜头里的东西 1 秒内到位，到位后停留不超过 0.5 秒就切；镜头层让每一帧都在动。
- **主画幅出演示片**：当 `meta.json` 配了多种切换时（如官方范例或用户明确要对比），每种切换在包的主画幅（`meta.json` 的 `full`，如 `16x9`）出一支完整演示片，同一张分镜表，只换品牌色、画面组织或画风；用户轻量包 `meta.json` 只配 1 项时就只出这一支。部件仍按横竖两种构图写，字幕和主体留在横竖都安全的区域，用户要竖版时能直接出；做完把主画幅临时改成另一画幅跑一次 `--quick`，看竖版有没有出界。
- **切换片段（可选）**：只在「要给别人切换着比风格」且 `meta.json` 配了多种切换时出——一支 15 秒左右的短片（`clip.js` / `clip_sound.py`），每种切换一支。**画幅跟随主演示片**：主片只出一种画幅就只出那一种，不为了切换片段另做另一画幅。完整演示片必需的是三件（`segments.json`、`scene.js`、`sound.py`）；已有的包升级时，原来的 15 秒演示可以直接当切换片段，它的内容也都排进完整演示片。
- **不带旁白**：靠字幕、文字和配乐讲。声音是铺底、每个部件的入场音效、章与章之间的起伏，同一个调。
- **体积**：每个包的素材合计不超过 10 MB（靠复用素材和代码做运动）；完整演示片每个视频不超过 20 MB，切换片段和轻量演示片照 1 级的上限。视频放 Release、不进仓库。

### 完整部件能力目录（按需选用 / 满配参照）

部件分两种。**分镜**在这里指能排进分镜表的一种呈现形式：**整屏部件**单独占一个镜头的时间、画满整屏（`meta.json` 里标 `"seg"`）；**叠加部件**（标注、光标、圈注、印章、信息条）叠在别的镜头上出（分镜表那一行的 `over`），位置取宿主部件的返回值，不单独占时间。**层**贯穿全片、不占时间。

下面这张目录穷举了一个成熟风格包可以覆盖的所有镜头与层：
- **做轻量起步包时**：把它当**能力点菜单**，只按当前片子的实际需要挑 4–8 个核心部件 + 基础层（不凑数、不硬写用不上的）。
- **做长期满配包或本仓库官方范例包时**：以 `dark-keynote` 为参照物，**但 45 是参照、不是配额**。它有 45 种分镜（40 种整屏部件、5 种叠加）和 7 个层——这是**包的能力数**；它的 `demo/segments.json` 实际排了 **44 行**（有的叠加只跟特定整屏部件搭配，不必每行都出现），两个数不要混。满配包的**下限**是：整屏部件 ≥30 种、叠加 ≥5 种、层 7 个；按题材往外发散，超过 45 更好，不必凑数，也不要求正好 45。题材窄的包（素材类型单一）够不到下限时，在 `STYLE.md` 里写明理由，检查按下限判。满配时下表各组都要有，同一组里的形式也要各不相同（不能两种都是「图表 + 大数字」）。题材和素材不同，分镜也会不同（新闻包会有滚动出处、分屏，生成类的包会有镜头卡、画风并排），下表的例子是参照，不是要照抄的清单，按包的题材往外发散。

|---|---|---|

### 样式查表

`lookup.json` 让接策划的人照表定样式（[storyboard.md「定样式」](storyboard.md#定样式)），不凭感觉挑部件。**官方包和完整满配包必填**（`build_index.py` 会查）；**用户项目里的轻量起步包可选**（缺时 `plan5.py` 只提醒不报错），也可以先只写已有部件、其余主角用 `instead` 回退，等后续扩充部件时再补齐：

```json
{"note": "这个包的字号大概多大、哪些主角用代替",
 "lead": {"一个数": {"part": ["bigNumber"]},
          "实物": {"instead": ["reveal"], "note": "包里没有实物框，用大字揭示代替"}},
 "sizes": {"bigNumber": {"top": ["prefix", "to", "suffix"], "mid": ["label"], "small": ["src"]}},
 "motion": {"tension": {"1": {"min": 5, "max": 9, "pop": false}, "2": {"min": 3, "max": 6, "pop": true},
                        "3": {"min": 2, "max": 3.5, "pop": true}},
            "pace": {"快": 0.8, "中": 1, "慢": 1.25},
            "mood": {"紧": "……", "松": "……", "稳": "……", "扬": "……"}}}
```

- `lead`：15 种主角（一个数、两数对比、走势、构成、排名、表格、流程、清单、一句话、问答、地图、实物、人、场景、界面）一个不少。包里有合适部件的写 `part`（可以几个，第一个是首选）；没有的写 `instead`（代替的部件）和 `note`（为什么），用了就是偏离，接的人在下游回报记一行。
- `sizes`：`lead` 里出现的每个部件都要有，键是部件在 `pack.js` 里的名字；`top`、`mid`、`small` 是这个部件的 `o` 里哪些键落在顶档、中档、小档，嵌套的写点路径（`items.label`，数组里每项都取）。顶档放策划的「最大的字」。
- `motion.tension`：张力 1–3 每格的秒数区间（`min` ≤ `max`）和要不要弹出（`pop`）；`pace`：段的节奏乘在秒数上的系数，快、中、慢都要有；`mood`：段的情绪紧、松、稳、扬各一句动效的感觉（缓入、回弹、停顿……）。
- 新加部件时一并加进 `sizes`，适合某种主角的补进 `lead`。

### 六条做法

1. **一个品牌色推出整套配色**：主题函数只收一个品牌色，背景、文字、辅助色、光晕都从它算出来（调亮度、调饱和度、取补色）。换品牌只改这一个参数。用户自用轻量包先保证选定的品牌色清晰耐看即可；做通用满配包或官方展示包时，拿至少三种差别大的颜色（比如紫、橙、绿）试，看哪种会脏、会看不清。
2. **部件只管自己那个镜头**：每个部件的签名都是 `(画布, 主题, 本地时间, 内容)`。本地时间从这个镜头开始时算 0，可以是负数（还没开始）。部件负责自己的入场和停留，不负责离场，离场交给转场。要被叠加的部件返回可标注的位置（如代码的每一行、按钮、散点里的那个点）。
3. **分镜表是一个数据文件**：`demo/segments.json`，每行是「用哪个部件、几拍、用哪种转场进来、放什么内容、本地时间倍速、叠什么部件、配哪几句字幕」，开始时刻按顺序累加。画面和声音都读它，时刻只记一处；改顺序、加一个镜头、调时长都只改这个文件。`scene.js` 的 `dur` 要等于总长（不等时报错）。
4. **转场拿两个整帧**：转场函数收「前一个镜头的画法」和「后一个镜头的画法」，在进度 0–1 之间把两者混起来（光边、推移、叠化、缩放穿越、遮罩擦除、闪白、翻转）。两边都带背景，叠化不会淡到黑。约定用法写进 STYLE.md，比如进章节闪卡用光边、闪卡进第一个镜头用推移、数字砸下前用闪白。
5. **字幕是代替旁白的说明文字**：写这个镜头画面没写出来的话，不和同屏的要点文字重复；按阅读速度排，每秒约 4–5 个字，结束时刻按字数算。镜头短，字幕不跟镜头走：每章一句，放在章节闪卡上，跨后面几个镜头。叠在最上层，放在横竖都安全的区域。
6. **声音跟分镜表同一条时间轴**：每个部件一个入场音效，转场各有各的音；铺底按章换和弦（同一个调里走），正文镜头有轻的节拍，章节闪卡和片尾节拍退下、只留长音，章首一记重击再回来。

分镜表的字段（`demo/segments.json`，键名以 `packs/dark-keynote/demo/segments.json` 为准）：

| 键 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 顶层 `brand` | 对象 | ✓ | 品牌信息（名字、副题等），供部件读取，用法见 `demo/scene.js` |
| 顶层 `tr` | 对象 | ✓ | 每种转场的时长（秒），键是转场名：`edge`/`push`/`fade`/`zoom`/`wipe`/`flash`/`flip` |
| 顶层 `segs` | 数组 | ✓ | 一行一个分镜，开始时刻按 `d` 顺序累加；`scene.js` 的 `dur` 要等于总长 |
| 行 `part` | 字符串 | ✓ | 用哪个整屏部件（`pack.js` 里注册的名字） |
| 行 `d` | 数字 | ✓ | 这个分镜几秒（整拍，1.5–2.25 秒） |
| 行 `o` | 对象 | ✓ | 传给部件的内容，键随部件而定（可为 `{}`） |
| 行 `tr` | 字符串 | | 从上一个分镜怎么接进来，取值是顶层 `tr` 的键 |
| 行 `speed` | 数字 | | 本地时间倍速（默认 1）：小于 1 慢放，大于 1 快放 |
| 行 `over` | 字符串 / 数组 | | 叠在上面的叠加部件 |
| 行 `cues` | 数组 | | 这一行配的字幕 |

### 出片和检查

用 1 级的 `batch.py`：`pack:<名字>@<键> --ar <主画幅>` 出这一种的演示片（`meta.json` 写了 `full` 时，按完整演示片 20–90 秒校验；轻量包 10–25 秒验证片**不要写 `full`**，按 5–30 秒区间校验），`--ar <另一画幅>` 出它的切换片段，不带 `--ar` 两种都出。演示片的 `--quick` 另外每个镜头抽一帧（镜头的 3/4 处，有分镜表时按表取，没有时每 2 秒一帧），拼成 `out/quick/<名字>-<键>-<画幅>.jpg`，格子上标第几个镜头和时刻，逐格看：文字有没有出界、压住字幕，转场接得上，角标该隐的地方隐了。检查项同 1 级，完整演示片时长 20–90 秒、每个视频不超过 20 MB；再对着总览图看有没有两格长得一样。

### STYLE.md 写什么

写给以后做这个项目视频的人和 AI 看，每条都要能照着检查：

- **分化方向与当前配置**：本包选定的分化维度与默认配置（如主品牌色、画面组织或画风），以及日后怎么加新切换、怎么按需扩充部件。
- **调色板**：品牌色怎么推出其他颜色，背景、文字、强调各用哪个，强调色在一个画面里最多占多少。
- **字体**：标题、正文、数字、等宽各用什么，字重和字号比例。
- **版式**：栅格、安全区，横竖两版各自的主体位置。
- **运动**：用哪几种缓动，入场时长，节拍，什么动作落在拍点上。
- **声音**：铺底和音效的音色、调、音量关系。
- **禁止项**：这个风格里绝对不能出现的东西（比如第二个强调色、圆形图标、弹跳缓动）。

写好后在用户项目的规范文件（`AGENTS.md`、`CLAUDE.md` 之类）里加一行链接到它，不要整份复制，免得两处不一致。

### 交付

- **轻量起步包**：用户选定 1 套配置的轻演示片（或先出片后抽包时的首片典型样片）、`pack.js`、部件表 `README.md`、`STYLE.md`（附 `CHANGES.md` 和单帧对比图）。
- **完整包 / 多切换包**：每种切换一支完整演示片（主画幅）和可选的另一画幅 15 秒切换片段、部件表（`README.md`，`meta.json` 的 `parts` 标明整屏部件还是层）、`lookup.json`、`STYLE.md`。

用户看过演示片（或首片典型样片）点头，风格包才算定下来。

### 跨项目保存与复用（`~/aicv-my-styles/`）

做完并通过验收的风格包，可以存到 Skill 目录之外的个人全局风格库 `~/aicv-my-styles/<包名>/`（更新 Skill 不会覆盖它；可用环境变量 `AICV_MY_STYLES` 指定别的路径）：

```bash
python3 new_pack.py --save ../packs/<包名>    # 复制进 ~/aicv-my-styles/ 并更新 ~/aicv-my-styles/README.md 索引
python3 new_pack.py --list                   # 列出已保存的所有个人风格包
```

`new_pack.py` 创建时直接加 `--my-styles` 也会写入这里。`batch.py`、`check_storyboard.py` 和 `check_plan.py` 都会**自动扫描** `~/aicv-my-styles/`，以后换到任何新项目写 `pack:<包名>` 都能直接用，不用手动传 `--pack-root`。

## 整片

完整出片（[film.md](film.md)）第 5 步（典型样片）、第 6 步（渲染整片）用自带出片工具的 `tools/film.py`，在拷进项目的 `video/` 下运行，输入是 `videos/<短名>/`。先照 [sound.md「完整出片的配音流程」](sound.md#完整出片的配音流程) 用 `tools/voice.py` 配好旁白、写好 `timing.json`。

```bash
python3 tools/film.py ../videos/<短名> P2 --quick     # 改代码时：本段每 2 秒半分辨率抽一帧，检查，出总览图 out/quick/P2.jpg
python3 tools/film.py ../videos/<短名> --typical      # 第 5 步：typical 标的段各出一支带声音的典型样片到 typical/
python3 tools/film.py ../videos/<短名> all -j 2       # 第 6 步：各段整帧渲染（无声）到 out/seg/，逐段检查
python3 tools/film.py ../videos/<短名> --join         # 接片、混音、整片自检，出成片和报告
python3 tools/film.py ../videos/<短名> --sound        # 只混整片的声音到 out/mix.wav，试听
```

- **一段一个场景**：`videos/<短名>/segments/<段号>.js`，写法同 1 级样片的 `scene.js`（每帧只由时间 t 决定，横竖构图看 `LAND`），不写 `dur`：段长取 `SEG.dur`，每句的起止、逐字时间用 `say`、`sayP`、`subAt` 读（[samples/API.md](samples/API.md)「完整出片的段」），不手估。几段共用的颜色、字幕、转场放一个文件，用 `needs` 载入；素材放 `videos/<短名>/assets/`，`asset()` 指向那里。画幅取分镜脚本的 `ar`。没有旁白的段按配乐节拍或段的 `sec`。段里写了分镜（`shots`）的，用 `drawShots` 一个分镜一个函数地画，起止从 `SEG.shots` 读，不手写切点（见 [film.md「分镜」](film.md#分镜-shots)）。
- **转场**：只用 `unify.trans` 里的那几种，画在相邻两段的接口上，前后段各管一半。淡入淡出淡到背景（留着纹理），不淡到纯黑：整片自检把 0.05 秒以上的黑段算 ✗。
- **声音**：可选的 `videos/<短名>/sound.py` 写 `score(m, T)`，配乐和音效写在整片的一条时间轴上、跨段连续（C 类用 `synth.py`，T、G 类用 `assets.json` 里允许再分发的曲子）；旁白由工具照 `timing.json` 摆，说话时配乐压低约 9 dB，最后定到 −14 LUFS、真峰值不超过 −1 dBTP。不把各段混好的声音拼起来。
- **单段检查**（`all`、`--quick`、`--typical` 都查）：脚本报错、黑屏或白屏、画面不动、静音、削波、段长 10–60 秒，可选 `--max-mb`；一句话的时间里画面主区一块都没变的列出来提醒。再看 `out/sheets/<段号>.jpg` 的抽帧和可疑的帧（同 1 级「出片和自检」）。
- **没变的段不重渲**：段代码和它 `needs` 的文件、`lib/`、`player.html`、本段的 `timing.json` 条目、`assets.json` 都没变就跳过；`--force` 全部重渲。
- **整片自检**（`--join`）：总时长等于各段之和、没有 0.05 秒以上的黑段、帧间隔均匀、响度 −14 ± 1 LUFS、真峰值 ≤ −1 dBTP、旁白在成片音轨里的位置和 `timing.json` 差不到一帧；结果写进 `out/report.md`。再听一遍接缝。
- **看画面时的两个时间**：`player.html` 的 `?t=` 是**段内时间**（0 = 这一段开头），段起点看 `timing.json`；用成片核对要 `ffmpeg -ss <全片秒>`（全片秒 = 段起点 + 段内秒）。报「第几秒有个元素出界」这类问题时先说清用的是哪个，免得两处对不上。
- **交付**：`out/<短名>-<画幅>.mp4`、每段的抽帧拼图 `out/sheets/<段号>.jpg`、`out/report.md`（段长表：段、段的 `sec`、实际秒数；音色；响度；检查结果）。封面、平台版本、附带短片不在工具里，用户要时另做。
- **长任务**：整片可能跑半小时以上，脱离会话运行、日志写文件，进程号由任务自己写进文件，例如在 `video/` 下 `nohup sh -c 'echo $$ > ../videos/<短名>/out/film.pid; exec python3 tools/film.py ../videos/<短名> all -j 2' > ../videos/<短名>/out/film.log 2>&1 &`（`out/` 先建好）。渲染、回听经 `tools/heavy.py` 排队，同一台机器上一次只跑一个；`-j` 在 4 核 15 GB 的机器上最多 2。
