# 出样片与做风格包

[← 返回 SKILL](SKILL.md)

讲 1 级（样片）和 2 级（风格包）具体怎么做，以及完整出片的[整片](#整片)规矩。提示词怎么写看 [prompting.md](prompting.md)，配声音看 [sound.md](sound.md)。下面提到的代码都随本 Skill 一起安装：`samples/`（出片工具和每个已验证风格的样片代码）、`packs/`（风格包），不用联网取。

## 动手之前

1. **确认技术路径在用户项目里跑得通**：要浏览器（Canvas 2D、WebGL、SVG）就确认有 Chromium 或 Playwright；要 GPU 就确认 WebGL2 能开；要配声音就确认有 Python 和 numpy、scipy；出视频要 ffmpeg。缺什么先说，不要写到一半才发现。
2. **优先改现成代码**：条目有「样片代码」的，从 `samples/<编号>/` 改，比只拿提示词重写稳定得多；有「风格包」的，直接用 `packs/<名字>/`。只有「技术（建议）」的条目没人验证过，要向用户说明效果靠试。
3. **用用户的真东西**：品牌色、字体、产品名、真实的一句文案。用占位文字做出来的样片，用户很难判断合不合适。

## 1 级：样片

目标是 3–5 秒、横竖两版，让用户判断「这个风格放在我的项目里像不像样」。

### 自带的出片工具

用户项目已经有 Remotion、Motion Canvas 这类管线的，用它自己的，样片代码只当画法参考。没有的，用本 Skill 自带的这套：

```bash
cp -R <本 Skill 目录>/samples ./video     # 拷进用户项目再改，不要直接改 Skill 安装目录（更新 Skill 会覆盖）
cd video && npm install                  # 字体和绘图库装进 node_modules/，出片时从本地载入，不联网
export AICV_SKILL=<本 Skill 目录>          # new.py 从这里读风格条目
python3 batch.py C-013 --quick           # 先原样跑通一个样片，确认环境没问题
python3 new.py C-013                     # 或：给还没有样片的风格起骨架（已有的文件不覆盖）
```

要 Node.js 18 以上、Python 3（Playwright 并装好 Chromium、Pillow、numpy、scipy）和 ffmpeg；浏览器可用环境变量 `CHROME` 指定。函数速查见 [samples/API.md](samples/API.md)，`batch.py` 的用法写在它文件开头。T 类、G 类样片只带了代码和 `assets.json`（素材清单），素材本身不随 Skill 安装（风格包 `packs/` 的演示素材除外，随包一起装）：T 类可以照 `assets.json` 用 `tools/assets.py` 重新下载，G 类要用户按 [materials.md「配置生成服务」](materials.md#配置生成服务) 配好服务再生成，或换成自己的素材。

**改的顺序**（照这个来，比从零设计稳）：

1. 拷对应风格的 `samples/<编号>/`，原样跑通 `--quick`（画面和声音都过）。
2. 换内容：题材、主体、文字、品牌色、时长，一次只改一处，每改一处跑一次 `--quick`。
3. 声音单独试：`python3 batch.py <编号> --sound`，别等画面全做完才第一次跑。
4. 画面都对了，再加细节。**细调最多 3 轮**（一轮 = 改一处、跑一次 `--quick` 看截图）：3 轮后不管满不满意，先去掉 `--quick` 出完整的横竖两版交给用户，把还想改的地方列出来，由用户决定要不要再调。不要停在半成品。

**哪些照用、哪些自己来**：

| 层 | 内容 | 怎么对待 |
|---|---|---|
| 管线 | `lib/lib.js`、`lib/synth.py`、`batch.py`、`render.py`、`player.html`；完整出片另有 `tools/voice.py`、`tools/film.py` | 照用，不要重写；时间驱动、截帧、合成声音、自检都在里面 |
| 画法 | 样片里怎么做出这种风格：镂空、光照、纹理、笔触、分层、运动方式 | 可以借，按用户的主体重新组合 |
| 内容 | 样片里的角色、场景、构图、配色、文字、配乐旋律 | 换成用户自己的；样片只是示范，主体和构图不能和样片一样 |

### 写法

- **每帧只由时间 t 决定**：画面写成 `draw(t)`，不依赖上一帧的状态，不用 `Math.random()`，随机数用带种子的发生器。这样可以任意跳帧检查，逐帧导出也不会掉帧、错位。
- **横竖两版分别构图**：竖版不是横版裁出来的。主体在横版里左右排，到竖版里通常改成上下排；字号、留白按短边缩放。
- **先定节拍**：入场、强调、收尾落在拍点上，声音也按同一个拍子放。本库样片用 160 BPM（一拍 0.375 秒，3 秒正好 8 拍）。
- **标志元素要画出来**：提示词里写的 3–5 个标志元素每个都要在画面里认得出，禁止项一条都不能出现。
- **文字**：中文要折行（标点不放行首），字体等加载完再画第一帧，长句在竖版里会不会挤出画面要单独看。

参考写法：[样片骨架和 API](samples/API.md) · [一个完整样片（C-044）](samples/C-044/) · [合成器 synth.py](samples/lib/synth.py)

### 出片和自检

逐帧截图再用 ffmpeg 合成视频，是最不挑环境的办法；用户项目已经有 Remotion、Motion Canvas 这类管线的，就用它自己的。交给用户之前自己先查一遍：

- 先看数字：时长、帧数、文件大小、首帧和末帧是不是全黑或全白。
- 再看抽帧拼图：每隔半秒到一秒取一帧拼成一张图，一眼看出节奏和构图。
- 只有可疑的那几帧才单独放大看：文字出界、元素重叠、竖版挤压、字体没加载成方块。
- 和风格的缩略图 `images/<编号>.jpg` 并排看：标志元素认不认得出；主体不该被做成虚的、糊的（只有提示词要求的地方才虚化）。
- 和样片 `samples/<编号>/` 的画面比：主体、构图要是用户自己的，不能只是换了颜色的样片。

### 交付

横屏 16:9 和竖屏 9:16 各一段视频，加一张抽帧拼图。一次给 2–3 个候选，每个附一句「为什么选它」，让用户挑。用户点头之前不要往下做 2 级。

## 2 级：风格包

用户通过的风格，做成一套能反复用的代码，加一份写进项目规范的风格说明。以后这个项目的视频都按它来，换内容不换风格。本库有三个范例：[dark-keynote 暗色科技发布会](packs/dark-keynote/)（C 类，切换品牌色）、[news-brief 新闻资讯解说](packs/news-brief/)（T 类，切换画面组织）、[style-swap 分镜换画风](packs/style-swap/)（G 类，切换画风），下面的做法都能在它们里面找到对应代码。

### 包里有什么

| 文件 | 是什么 |
|---|---|
| `pack.js` | 主题和部件 |
| `sound_kit.py` | 每种部件出现时放什么音，外加一段铺底 |
| `STYLE.md` | 风格说明：调色板、字体、版式、运动、声音、禁止项 |
| `meta.json` | 名字、部件清单、几种演示用的切换（`accents` 品牌色，或 `variants` 加 `switch` 切换别的维度；第一种是默认） |
| `demo/` | 演示片：把所有部件排成一支 15 秒左右的短片，每种切换各出横竖两版；T、G 类的包另有 `assets/` 和 `assets.json`（素材随 Skill 安装，拷出去就能出片） |

### 五条做法

1. **一个品牌色推出整套配色**：主题函数只收一个品牌色，背景、文字、辅助色、光晕都从它算出来（调亮度、调饱和度、取补色）。换品牌只改这一个参数。做完要拿至少三种差别大的颜色（比如紫、橙、绿）试，看哪种会脏、会看不清。
2. **部件只管自己那一段**：每个部件的签名都是 `(画布, 主题, 本地时间, 内容)`。本地时间从这一段开始时算 0，可以是负数（还没开始）。部件负责自己的入场和停留，不负责离场，离场交给转场。
3. **用分段表排片子**：一支片子就是一张表，每行是「从第几秒开始、用哪个部件、放什么内容」。每帧先查表找到当前段，再把本地时间传给部件。改顺序、加一段、调时长都只改表。
4. **转场拿两个整帧**：转场函数收「前一段的画法」和「后一段的画法」，在进度 0–1 之间把两者混起来（擦除、推移、光边）。这样任何两个部件之间都能接，部件自己不用知道前后是谁。
5. **字幕和声音跟分段表同一条时间轴**：字幕是一串「开始、结束、文字」，最后叠在最上层，放在横竖两版都安全的区域。声音按同一张表的时刻放：每个部件一个入场音效，加一段贯穿全片的铺底，都在同一个调上。

通常要覆盖的部件：片头、讲解（分步骤）、数据（柱状和大数字）、转场、字幕。用户项目里常出现别的画面（比如人物介绍、代码演示），就再加对应的部件。

### T 类、G 类的包：切换别的维度

素材做的片子，颜色往往由照片、生成的图决定，换品牌色意义不大。这时挑一个用户真正会换的维度做成切换，其余全部固定：

- **只切换一个维度，写在 `meta.json` 的 `switch` 里**（如「画面组织」「画风」），几种取值写在 `variants`：`[键, 中文名, 英文名, 值]`。出片工具把键传给播放器的参数 `v`，场景里用 `Q.get('v')` 读；同一张分段表、同一套部件、同一条声音，切换只改这一个参数。
- **T 类按「画面组织」切**（[news-brief](packs/news-brief/)）：照片怎么上屏——单图推拉、按深度图切成远中近三层的 2.5D 视差、几张同时上屏的拼贴分屏。每种画面组织是一个对象，`draw()` 画出这一段的照片，并返回文字卡的位置和照片上某点的屏幕坐标，标题、数据卡、标注都按它返回的位置画，所以三种共用同一套部件。
- **G 类按「画风」切**（[style-swap](packs/style-swap/)）：提示词拆成「镜头段 + 风格段 + 约束段」，写在一个数据文件里；镜头段每个镜头一段，约束段全片共用，**只有风格段随画风换**。脚本把三段拼成每张图的完整提示词写进 `assets.json`，再统一生成。画风一换就是整套新图，剪辑代码一行不动。
- **加第 4 种**：在 `variants` 加一行；T 类再写一个画面组织对象，G 类在数据文件里加一行风格段、补生成这一套图。每个包的 STYLE.md 写清楚具体步骤。
- **素材随包走**：包的 `demo/assets/` 随 Skill 一起安装（每个包合计不超过 10 MB），用户拷出去不用重新下载、不用配生成服务就能先跑通演示片；换成自己的素材时照 `assets.json` 记出处、许可或提示词。

### STYLE.md 写什么

写给以后做这个项目视频的人和 AI 看，每条都要能照着检查：

- **调色板**：品牌色怎么推出其他颜色，背景、文字、强调各用哪个，强调色在一个画面里最多占多少。
- **字体**：标题、正文、数字、等宽各用什么，字重和字号比例。
- **版式**：栅格、安全区，横竖两版各自的主体位置。
- **运动**：用哪几种缓动，入场时长，节拍，什么动作落在拍点上。
- **声音**：铺底和音效的音色、调、音量关系。
- **禁止项**：这个风格里绝对不能出现的东西（比如第二个强调色、圆形图标、弹跳缓动）。

写好后在用户项目的规范文件（`AGENTS.md`、`CLAUDE.md` 之类）里加一行链接到它，不要整份复制，免得两处不一致。

### 交付

每种切换（品牌色、画面组织、画风…）的横竖两版演示片（让用户自己切换着比）、部件清单（每个部件的调用方式和内容字段）、STYLE.md。用户看过演示片点头，风格包才算定下来。

## 整片

完整出片（[film.md](film.md)）第 5 步（典型样片）、第 6 步（渲染整片）用自带出片工具的 `tools/film.py`，在拷进项目的 `video/` 下运行，输入是 `videos/<短名>/`。先照 [sound.md「完整出片的配音流程」](sound.md#完整出片的配音流程) 用 `tools/voice.py` 配好旁白、写好 `timing.json`。

```bash
python3 tools/film.py ../videos/<短名> P2 --quick     # 改代码时：本段每 2 秒半分辨率抽一帧，检查，出总览图 out/quick/P2.jpg
python3 tools/film.py ../videos/<短名> --typical      # 第 5 步：typical 标的段各出一支带声音的典型样片到 typical/
python3 tools/film.py ../videos/<短名> all -j 2       # 第 6 步：各段整帧渲染（无声）到 out/seg/，逐段检查
python3 tools/film.py ../videos/<短名> --join         # 接片、混音、整片自检，出成片和报告
python3 tools/film.py ../videos/<短名> --sound        # 只混整片的声音到 out/mix.wav，试听
```

- **一段一个场景**：`videos/<短名>/segments/<段号>.js`，写法同 1 级样片的 `scene.js`（每帧只由时间 t 决定，横竖构图看 `LAND`），不写 `dur`：段长取 `SEG.dur`，每句的起止、逐字时间用 `say`、`sayP`、`subAt` 读（[samples/API.md](samples/API.md)「完整出片的段」），不手估。几段共用的颜色、字幕、转场放一个文件，用 `needs` 载入；素材放 `videos/<短名>/assets/`，`asset()` 指向那里。画幅取分镜的 `ar`。没有旁白的段按配乐节拍或分镜的 `sec`。
- **转场**：只用 `unify.trans` 里的那几种，画在相邻两段的接口上，前后段各管一半。淡入淡出淡到背景（留着纹理），不淡到纯黑：整片自检把 0.05 秒以上的黑段算 ✗。
- **声音**：可选的 `videos/<短名>/sound.py` 写 `score(m, T)`，配乐和音效写在整片的一条时间轴上、跨段连续（C 类用 `synth.py`，T、G 类用 `assets.json` 里允许再分发的曲子）；旁白由工具照 `timing.json` 摆，说话时配乐压低约 9 dB，最后定到 −14 LUFS、真峰值不超过 −1 dBTP。不把各段混好的声音拼起来。
- **单段检查**（`all`、`--quick`、`--typical` 都查）：脚本报错、黑屏或白屏、画面不动、静音、削波、段长 10–60 秒，可选 `--max-mb`；一句话的时间里画面主区一块都没变的列出来提醒。再看 `out/sheets/<段号>.jpg` 的抽帧和可疑的帧（同 1 级「出片和自检」）。
- **没变的段不重渲**：段代码和它 `needs` 的文件、`lib/`、`player.html`、本段的 `timing.json` 条目、`assets.json` 都没变就跳过；`--force` 全部重渲。
- **整片自检**（`--join`）：总时长等于各段之和、没有 0.05 秒以上的黑段、帧间隔均匀、响度 −14 ± 1 LUFS、真峰值 ≤ −1 dBTP、旁白在成片音轨里的位置和 `timing.json` 差不到一帧；结果写进 `out/report.md`。再听一遍接缝。
- **交付**：`out/<短名>-<画幅>.mp4`、每段的抽帧拼图 `out/sheets/<段号>.jpg`、`out/report.md`（段长表：段、分镜的 `sec`、实际秒数；音色；响度；检查结果）。封面、平台版本、附带短片不在工具里，用户要时另做。
- **长任务**：整片可能跑半小时以上，脱离会话运行、日志写文件，进程号由任务自己写进文件，例如在 `video/` 下 `nohup sh -c 'echo $$ > ../videos/<短名>/out/film.pid; exec python3 tools/film.py ../videos/<短名> all -j 2' > ../videos/<短名>/out/film.log 2>&1 &`（`out/` 先建好）。渲染、回听经 `tools/heavy.py` 排队，同一台机器上一次只跑一个；`-j` 在 4 核 15 GB 的机器上最多 2。
