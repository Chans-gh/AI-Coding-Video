# 接策划：从 plan.md 到分镜和逐字稿

内容由 [ai-content-planner](https://github.com/Chans-gh/AI-content-planner) 策划好、交接过来时读这份。本 Skill 只管形式（风格、分镜、画面、出片），不改要讲的内容。

## 1 先认格式和状态

打开用户项目里的 `plans/<短名>/plan.md`：

- 标题下面那行（不算空行）必须是 `格式：ai-content-planner/1`。没有这一行或版本号不是 1，停下，请用户更新本 Skill 或策划，不要猜着读。
- 状态行必须是「已交接」。「回流中」等策划处理完；别的状态（整理中、待确认、补齐中）先回策划。
- 立意的「输出形式」要是视频，不是的交给对应的 Skill。

## 2 读什么

- `plan.md`：立意（「篇幅与规格」里有时长、画幅、语言、有没有旁白；「不讲什么」照着避开）、段落表、缺口表。段落表六列：`段 | 作用 | 受众收益 | 核心内容 | 素材编排 | 篇幅`，按成品里的顺序排，段号（`P1`）可以不连续。
- `research.md`：每个 `## U1` 一节有一张数据表，`U1-1` 一条，列是内容、种类、来源、必须写清的、状态。资料清单有每份来源的链接。
- 「核心内容」照写，不另起炉灶；里面括号里的 U 编号就是这句话的依据。

选风格照 0 级（`SKILL.md`「三级用法」和「怎么查」）：按立意的用途、给谁看、怎么讲给 2–3 个候选，用户定一个。

## 3 分镜：`videos/<短名>/storyboard.json`

产物放 `videos/<短名>/`，不写进 `plans/`。

```json
{"plan": "plans/<短名>/plan.md", "style": "C-036", "ar": "9:16",
 "segments": [{"seg": "P1", "title": "冷开场", "content": "…", "sec": 15, "lead": "C",
               "uses": [{"what": "大字砸进来", "ref": "C-036"}, {"what": "发射录像慢放", "class": "T"}],
               "note": "…"}]}
```

| 字段 | 写什么 |
|---|---|
| `plan` | 来自哪份 `plan.md`，相对项目根目录 |
| `style`、`ar` | 选定的风格编号（或 `pack:风格包名`）、画幅（取自「篇幅与规格」） |
| `segments` | 按播放顺序，每项是一段分镜 |
| `seg` | 对应段落表的段号。一段策划可拆成几段分镜，各段写同一个 `seg`，按段落表的顺序排；每个段号至少用一次 |
| `title` | 这段分镜的短标题 |
| `content` | 这段讲什么：取自该段「核心内容」，拆开时写这一部分 |
| `sec` | 预计秒数。同一 `seg` 的几段加起来贴近该段「篇幅」，全片贴近目标时长 |
| `lead` | 本段主角类，`C`、`T`、`G` 之一：画面主要靠代码算（C）、真实素材（T）还是生成素材（G） |
| `uses` | 用到的技术，每条 `what` 写做什么；有对应样片的写 `ref`（样片编号或 `pack:风格包名`，类别跟着样片走），没有的写 `class`（C/T/G）。`ref`、`class` 只写一个。这里的 `ref` 指样片，和逐字稿里指事实的 `ref` 不是一回事 |
| `note` | 编排说明：分几层、谁驱动时间（旁白句子、音乐节拍还是匀速）、怎么接进前后段。分镜时写打算，做完照实改，80–150 字 |

「素材编排」里写的素材和缺口表里归「下游」的行（要拍、录、生成的），落到对应段的 `uses`。

## 4 逐字稿：`videos/<短名>/script.json`

```json
{"plan": "plans/<短名>/plan.md",
 "segments": [{"seg": "P1", "vo": ["四十万零六千七百七十一公里。", "…"],
               "facts": [{"what": "离地球最远 252,756 英里（约 406,771 公里）", "ref": "U1-2",
                          "src": "https://…", "calc": "英里按 1.609344 换算成公里"}],
               "pace": {"lead": 1.2, "gap": 0.5, "min": 15}}]}
```

- `segments` 和 `storyboard.json` 的段按顺序一一对应，`seg` 照抄。
- `vo`：念的稿子，一句一项；数字按念法写（「四十万零六千七百七十一公里」）。没有旁白的片子写空数组。要字幕写法和念法不同，加顶层 `show`：`{"念法": "字幕写法"}`。
- `facts`：本段旁白和画面上的每个数字、事实各一条。`what` 写事实本身；`ref` 写依据的 U 编号（`"U1-2"`，整个单元写 `"U1"`），设定、虚构的写 `null`；`src` 写这条的来源链接（「来源」格写的是哪份资料，链接在资料清单的「位置」）；换算、推算的（种类 `B6`，来源写「用 U1-2、U3-1」）`src` 写 `null`，加 `calc` 写算法和用到的编号。
- `pace`（可选）：`lead` 旁白前留几秒，`gap` 句与句之间另留几秒给画面，`tail` 旁白后留几秒，`min` 本段最短几秒。

事实的规矩：

- 只引用状态「已核实」或种类「设定」的数据；「有冲突」「〔待核实〕」的不引用，也不自己挑一个数讲。
- 照写「必须写清的」：时区、口径、单位、版本。种类 `C4`（某方自己说的、计划）讲成「官方称」「按计划」。
- 确认记录里定过的讲法（例如只讲时段、不讲分钟数）照着讲。
- `ref` 都要能在 `research.md` 里找到；`seg` 都要在段落表里。交给用户前自己核一遍。

## 5 确认后出片

分镜和逐字稿给用户看，确认后进入制作，照 `making.md`：样片怎么写、出片和自检。素材的来源、许可和处理见 `materials.md`，配乐和旁白见 `sound.md`。

## 6 回流：做的时候发现缺东西

只许改 `plan.md` 的两处，不改别的，也不改 `research.md`：

- **缺内容**（缺步骤、缺解释、数字对不上、结论站不住）：缺口表加一行，`编号` 接最大的 Q 往后编，`段` 写段号或「全部」，`归谁=策划`、`提出于=下游`、`状态=待补`；状态行改成「回流中」，请用户转给策划处理。策划改回「已交接」后，按当时的段落表接着做，不恢复已删的内容。
- **缺画面**（缺一张图、一段录屏、一段生成素材）：自己处理。原来就在缺口表里的，做完把状态改成「已补」、写「怎么解决的」；新发现的照上面加一行，`归谁=下游`，不改状态行。
