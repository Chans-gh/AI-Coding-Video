[← 返回说明](README.md)

## 声音篇：总原则

声音分两层：背景层（配乐、环境声、动作音效）和人声层（旁白、对话）。公开风格库的导演指南（见 [sources.md](sources.md)）把声音排在评判标准的第一位，下面 7 条是从各风格的声音设计里提炼的通用做法。

1. **先定音乐时间轴，再做画面**：切点、关键动作、字幕出现都落在拍子上，音乐和画面共用一份时间表。
2. **每个看得见的动作都要有声音，音效跟材质走**：纸、木、金属、墨、玻璃、塑料各有各的声音。
3. **静音是工具**：高潮或笑点前给一拍真正的静音，连混响尾巴一起切掉。
4. **别用万能铺底**：避开“钢琴 + 弦乐”通用配乐和廉价的“嗖”声（卡通类除外），换成这种风格自己的乐器。
5. **混音层级**：人声在最上层；有人声时音乐压低 8–12 dB、环境声压低 3–6 dB；整体响度 −14 LUFS。8–12 dB 的压低只管完整出片；1 级样片的 `synth.assets` 压得轻（约 5 dB），不改，改了已出的样片声音会变。
6. **旁白要回听校对**：生成后逐句识别，每句的读音都要对上（比拼音，同音字写错不算念错）；多音字、数字、人名先改写再合成。做法见下面「完整出片的配音流程」。
7. **版权**：音乐和音效优先用代码合成，其次是 CC0、CC BY 或已购授权的曲库，并在片尾或说明里列出来源。

## 背景音乐与音效：按风格类别匹配

先按风格条目的「题材」找到一行，再把这一行写进提示词的“声音”部分。括号里是该类别中具体风格的实测做法。

| 风格类别 | 配乐（乐器与节奏） | 环境声 | 动作音效 |
|---|---|---|---|
| 手绘与绘画 | 独奏或小编制原声，60–100 BPM（水墨用古琴加箫，一笔画用一把大提琴拉一条不断的旋律，蜡笔绘本用音乐盒和玩具钢琴，白板用马林巴加木鱼的钟表感） | 纸面室内底噪、雨、风 | 笔刷摩擦、铅笔沙沙声、粉笔、马克笔吱声、墨滴 |
| 东方传统 | 民族乐器（皮影用锣鼓经，窗花剪纸用琵琶、古筝、二胡的喜庆室内乐，浮世绘用三味线、尺八、太鼓，纸雕灯影用古筝接笛子） | 夜虫、油灯噼啪、远处爆竹 | 剪刀、纸张折合、醒木、竹杆敲布幕 |

| 卡通与动漫 | 橡皮管用 1930 年代热爵士加滑哨，赛璐璐用城市流行或合成放克，科幻喜剧用特雷门琴 | 随场景 | 卡通音效：弹跳“boing”、“啵”、滑哨、冲刺风声（这一类可以用） |

| 电影年代与屏幕科技 | 默片用影院钢琴即兴；终端用模拟合成器加大段静音；HUD 用低频合成脉冲；后室不要配乐 | 放映机转动、胶片噪声、荧光灯嗡嗡声 | 打字机、继电器、扫描“哔”声 |

## 用代码合成声音：自带的电子音

本库样片的声音全部用代码现场合成，不调用任何第三方声音模型（TTS、AI 作曲），也不用曲库、录音和采样。每种乐器都是一个函数，用 numpy 和 scipy 算出波形，按时间点放到混音台上。同一份代码每次合成的声音完全一样，没有版权问题。合成器在 [samples/lib/synth.py](https://github.com/Chans-gh/AI-Coding-Video/blob/main/samples/lib/synth.py)，每个样片的配乐写在 `samples/<编号>/sound.py`。

| 想要的声音 | 合成方法 |
|---|---|
| 底鼓、拍手、踩镲、转场重击 | 频率快速下滑的正弦波；滤波后的噪声加衰减包络 |
| 古琴、吉他一类拨弦 | Karplus-Strong：一小段噪声在延迟线里反复低通 |
| 钟、钟琴、金属声 | FM 合成：调制器频率取载波的非整数倍 |
| 8-bit 游戏音 | 方波，可调占空比 |
| 贝斯、铺底和弦、合成器 | 两个略微失谐的锯齿波叠加，再低通 |
| 风声、墨晕、转场“嗖” | 带通噪声，中心频率随时间扫过去 |
| 木鱼、盖章、按键 | 短促的正弦泛音或带通噪声，几十毫秒内衰减 |
| CRT、荧光灯嗡嗡声 | 60 Hz 正弦加奇次谐波 |

写法：先列出画面里每个动作发生的时刻，比如字出现、印章落下、进度走满，每个时刻放一个对应材质的音；再垫一层低音或持续音，把节奏定在一个 BPM 上。上表“按风格类别匹配”里的乐器，大多能用这几种方法近似出来。

下面的 Kokoro 旁白音色，是给需要人声旁白的项目参考的；本库 C 类样片不用人声；T 类、G 类样片的旁白用语音合成服务的公开音色，配乐用公共领域或 CC0 的曲子，见 [materials.md](materials.md)。

## 完整出片的配音流程

完整出片（[film.md](film.md)）第 5 步（典型样片）、第 6 步（整片）照这里配旁白。稿子是 `script.json` 每段的 `vo`，一句一项，数字已经写成念法。配音用自带出片工具的 `tools/voice.py`（拷进项目的 `video/` 里，见 [making.md](making.md)「自带的出片工具」），在 `video/` 下运行，输入就是 `videos/<短名>/`：

```bash
python3 tools/voice.py ../videos/<短名> --dry-run   # 先看要请求几次、多少字；不请求
python3 tools/voice.py ../videos/<短名>             # 合成缺的句子、切句、排段长，写 timing.json
python3 tools/voice.py ../videos/<短名> --check     # 回听
```

已经有整稿录音的（用户自己录的、别处一次合成的整稿），用 `--import 整稿.mp3 --subs 字幕.json` 读进缓存，当成一次覆盖全部段的请求切回每句，不重配、不花钱；字幕的格式同适配命令返回的（`[{t0, t1, text, words 可选}]`），写法可以是屏幕上的（`show` 换过的）。之后改了哪句，照常只合成那一句。

1. **定音色**：默认用语音合成服务的公开音色，经 `AICV_TTS_CMD` 调用，不写死哪一家（配法见 [materials.md「配置生成服务」](materials.md#配置生成服务)），先用最便宜的模型试。不想用服务的，用本地 Kokoro：`pip install sherpa-onnx`，`export AICV_TTS_CMD="python3 tools/adapters/kokoro.py"`，首次用时下载模型（约 400 MB，放在 `~/.cache/aicv/models/`，不放进项目）；音色名照下面「旁白配音：按用途选音色」写（`zf_083`）。全片一个音色、一个语速，写进分镜的 `unify.voice`：`{"model", "voice", "speed"}`。用户换音色或语速，全部句子重做，不混用。
2. **先看预估**：`--dry-run` 打印要请求几次、多少字。按次、按字计费的服务先把这个数告诉用户。超过 `--max-chars`（默认 3000 字）或 `--max-requests`（默认 20 次）的，不加 `--yes` 不请求。
3. **合成按段、存按句**：一段里连着缺的句子请求一次（连着念，语气连贯，也省请求），按返回的逐字时间切回每句，存成 `vo/<段号>_<两位句号>.wav`。改了一句，只合成那一句：同音色、同语速、同文字的句子从句子池 `vo/cache/pool/` 复用，每次请求的原样返回存在 `vo/cache/req/`，所以重跑时长不变、不重复花钱。每次真实请求在 `vo/usage.jsonl` 记一行（时间、段号、字数、时长）。`vo/` 和 `timing.json` 建议随项目提交。
4. **切句**：停顿按每 5 毫秒的峰值电平找（低于 −45 dB、至少 0.06 秒），句尾轻的余音不算进停顿。句界放在两句之间真实的停顿里：从时间戳往后找声音真正停下的地方，下一句从停顿结束处开始；没有够静的停顿就在最静处切（会提醒）。切完查每句首尾 30 毫秒，高于 −45 dB（切在发音上，会听到断句）就报错，不写 `timing.json`。服务不返回字幕的，按句数在停顿里切，切不准自动改成一句一次请求。
5. **排段长**：照 `script.json` 的 `pace` 排，见 [film.md](film.md)「逐字稿」：第一句的声音从 `lead` 秒开始，下一句接在上一句有声部分结束后再隔 `gap` 秒，最后一句说完再留 `tail` 秒，段长取这个和 `min` 里大的，取整帧；没有旁白的段取 `min` 或分镜的 `sec`。结果写进 `videos/<短名>/timing.json`（格式见 [film.md](film.md)「时间」），画面的动画时刻、字幕都从这里读，不另估。算出的段长和分镜的 `sec` 差 20% 以上的会提醒：照实改 `sec`，告诉用户全片会长或短多少。
6. **回听**：`--check` 先核配好的句子还是不是现在的稿子（改了稿子没重配的，列出来停下），再逐句离线识别（中文用 SenseVoice，首次用时下载约 230 MB；其他语言用 faster-whisper），和稿子都转成无声调拼音再比，同音字不算错（识别器常把「氢键」写成「清箭」），数字两种念法都试。两个以上字母的英文词只查那里听到了东西，列出来请人听；一个字挪到相邻句的单独报「跨句挪字」，那是切句问题、不用改稿子。识别器总听错的词写在 `script.json` 顶层的 `heard`（`{"稿子里的词": ["听成的", …]}`），只影响回听。最后一行「0 句不一致」才算过；不一致的人再听，确实念错的（多音字、数字、英文）改写稿子里的念法，再跑一遍，只重做那一句。回听和渲染都经 `tools/heavy.py` 排队，同一台机器上一次只跑一个。
7. **和配乐统一混音**：旁白、配乐、音效放在同一条时间轴上一次混好：有旁白时配乐压低，整体响度 −14 LUFS 左右。整片和典型样片由整片工具混，见 [making.md「整片」](making.md#整片)，说话时配乐压低约 9 dB。
8. **记下来**：音色和模型就在 `unify.voice`，每句的文字在 `script.json`；Key、任务编号、带签名的链接不记（适配命令的日志只写在 `out/log/`，不提交）。

**克隆声音**：本 Skill 不做，本仓库的样片也不用克隆音色。用户要用自己的或获得授权的声音，由用户自己接第三方 Skill 或接口生成，把生成的文件当旁白放进来，照样一句一个文件、回听、量时长、按 `pace` 排。不克隆真人的声音冒充本人。

## 旁白配音：Kokoro-82M v1.1-zh 音色总览

Kokoro-82M v1.1-zh 是一个可以在本地 CPU 上跑的开源 TTS 模型（Apache 2.0，24 kHz），共 103 个音色：100 个中文音色来自龙猫数据的 100 位专业说话人，另有 3 个英文音色。

| 前缀 | 数量 | 说明 |
|---|---|---|
| zf_ | 55 | 中文女声，编号不连续（zf_001–zf_099 中的 55 个） |
| zm_ | 45 | 中文男声（zm_009–zm_100 中的 45 个） |
| af_maple · af_sol | 2 | 美式英语女声 |
| bf_vale | 1 | 英式英语女声，官方描述为“年长的英国女性” |

**官方没有给每个中文音色写描述，音色名只是编号。** 为了能区分，我用同样两段文字（一段科普讲解、一段童话叙述）把 100 个中文音色全部合成一遍（语速都设为 1.0），测了四项指标并分档：

- **音高档**：基频中位数。女声分低音（低于 200 Hz）、中低音、中音、中高音、高音（280 Hz 以上）；男声分低沉（低于 120 Hz）、中低音、中音、中高音、高音少年感（190 Hz 以上）。
- **语调**：句子里音高起伏的幅度。平稳适合播报和讲解，起伏大适合讲故事和角色。
- **语速**：同样文字每秒读出的字数，分偏快、中等、偏慢。
- **声音明暗**：高频多少。偏暗的听起来更柔或更厚，偏亮的更清脆。

这是声学测量结果，不包含年龄感、亲和力这类主观印象。定音色前请先到 [sherpa-onnx 试听页](https://k2-fsa.github.io/sherpa/onnx/tts/all/Chinese-English/kokoro-multi-lang-v1_1.html) 听一遍候选，那里每个音色都有同一段文字的试听（页面用编号标注：3–57 是 zf_，58–102 是 zm_，各自按音色名从小到大排列，如 3 是 zf_001、58 是 zm_009）。

## 旁白配音：按风格类别选音色

很多风格其实不需要旁白，靠字幕和音乐就够了。这张表先回答“要不要旁白”，再给音色。

## 对话与多角色配音

有对话时，关键是让观众闭着眼睛也能分清谁在说话。

1. **旁白和角色分开**：旁白用平稳的中音，角色用起伏大的音色。
2. **角色之间至少隔一个音高档**：如高音女声配低沉男声，或高音女声配中低音女声；同一档的两个音色很难分辨。
3. **同一角色全片固定音色和语速**，写进角色设定表。
4. **每句台词单独生成一个文件**，句间留 0.2–0.4 秒，方便对字幕和口型。
5. **情绪靠文案和节奏**：Kokoro 不会耳语、喊叫、哭或唱歌。害怕就用短句、慢语速、多停顿；兴奋就用感叹句和稍快语速。
6. **非人类角色**（机器人、吉祥物、游戏角色）可以不用人声：用打字“哔哔”声，或给合成人声加环形调制、带通滤波。

## 旁白提示词与调用代码

把下面这段加到前面通用模板的“声音”一行，把音色和语速换成上面表里选好的：

```text
声音：配乐用【风格类别对应的乐器】，音效跟画面材质走，高潮前留一拍静音。
旁白用本地 Kokoro-82M-v1.1-zh，音色【zf_083】，语速【0.95】；共【4–6】句，每句不超过 20 字。
多音字、数字、英文先改写成不会读错的写法。
有旁白时音乐压低 9 dB、环境声压低 4 dB，整体 −14 LUFS。生成后逐句回听，0 句不一致才进成片。
```

调用：自带出片工具的 [tools/adapters/kokoro.py](samples/tools/adapters/kokoro.py) 用 sherpa-onnx 跑 Kokoro v1.1-zh（不装 torch），按 `AICV_TTS_CMD` 的约定接进 `tools/gen.py` 和 `tools/voice.py`；单独试一句：`AICV_TTS_VOICE=zf_083 python3 tools/gen.py try tts`。sherpa-onnx 版用数字编号音色（`zf_083` 是 47），适配命令按音色名换算，编号顺序写在它开头。
