# 完整出片：从内容到整片

用户要「做一支 X 分钟的片子」时读这份。只要看看效果、挑风格、定一套风格的，走风格演示（`SKILL.md`「两条线」）。

产物都放用户项目的 `videos/<短名>/`：`storyboard.json`（分镜脚本）、`script.json`（逐字稿），之后是 `segments/`（每段的场景代码）、`vo/` 和 `timing.json`（配音和时间）、`typical/`（典型样片）和 `out/`（整片）。有策划时也不写进 `plans/`。

## 六步

每一步都要用户点头才往下；停在哪一步都行。

1. **定内容**：
   - 有策划（项目里有 `plans/<短名>/plan.md`，交接格式 2、状态「已交接」）：照 [storyboard.md](storyboard.md) 接，要讲什么不改，缺内容回流给策划。分镜脚本写 `plan`。
   - 无策划：轻量，不做大规模搜索、求证。整理用户给的内容，或从用户的主题和要求往外扩展；可以补一些数据和事实，但每条都标「待用户确认」（见「事实的规矩」），用户确认了才进成片。内容多、要查证的，建议用户先用 [ai-content-planner](https://github.com/Chans-gh/AI-content-planner)。需求写在分镜脚本的 `brief`，每段讲什么写在 `content`，不另建 `plan.md`。
2. **分段、分镜与样式**：一步做完：分段、每段讲什么、每段用什么样式（`uses`，一段可以混用几种风格、技术、素材），段里要切几个画面的再拆成分镜（`shots`：每个分镜画什么、几秒或跟哪几句旁白、用什么、从哪张图来、怎么接），同时定全片统一（`unify`），标 1–2 段做典型样片（`typical`）。用到生成素材（G 类）的段都拆到分镜，生成几张图、几段视频才能逐个对上；纯代码画、一个画面到底的段可以不拆。不先单独选一种风格；项目里已有风格包的，直接拿它当全片统一。查风格照 `SKILL.md`「怎么查」。写进 `storyboard.json`，`status` 写「草稿」，格式见下面「分镜脚本」。
3. **逐字稿**：每段念什么、画面上出现的每个数字和事实从哪来。写进 `script.json`，格式和规矩见下面「逐字稿」「事实的规矩」。分镜的 `vo` 指的是这里的句号，句子增删后跟着改。
4. **用户确认**：一次给用户看四样：段落表（段、讲什么、秒数、分镜数、样式、主角类）、每段的分镜表（分镜号、秒数、画面、类别、素材或参考图、对应哪句旁白、怎么接，合计几个分镜、其中几个是生成的）、全片统一、逐字稿和待确认的事实。两张表用检查脚本打印（见「检查」），不手抄。用户点头后分镜脚本的 `status` 改成「用户确认」，事实的 `confirm` 改成「用户确认」，用户不要的删掉、旁白跟着改。
5. **典型样片（含配音）**：用户看了再决定整片做不做、怎么改。
   - 开工前跑一遍 `--ready`（见「检查」），不过不做。
   - 做 `typical` 标的 1–2 段，用分镜脚本的画幅 `ar`，一段一个场景（`segments/<段号>.js`）。画面照 [making.md](making.md)「1 级：样片」的出片工具和改的顺序，从 `uses` 里 `ref` 的样片代码改；颜色、字体、字幕、转场服从 `unify`。素材照 [materials.md](materials.md)。
   - 先配音再定画面的时刻：照 [sound.md「完整出片的配音流程」](sound.md#完整出片的配音流程) 用 `tools/voice.py` 配这几段、回听到「0 句不一致」，它按 `pace` 排出段长和每句的起止写进 `timing.json`，动画、字幕跟着排；配乐和旁白统一混。
   - 出片用 `tools/film.py ../videos/<短名> --typical`，单段检查照 [making.md「整片」](making.md#整片)。
   - 交给用户：视频在 `videos/<短名>/typical/<段号>-<画幅>.mp4`，附同名的抽帧拼图、音色、段长（和段的 `sec` 比，差得多的照实改 `sec`）。
   - 不满意样式，回到第 2 步改样式，不直接改代码凑；只是音色不对，换音色重做这段的全部句子。
6. **渲染整片**：用户点头典型样片后才做。先用 `tools/voice.py` 配完全部段的旁白、回听通过，再 `tools/film.py ../videos/<短名> all` 分段渲染、单独检查，`--join` 接成整片、统一混音、自检，放 `videos/<短名>/out/`。用法和规矩见 [making.md「整片」](making.md#整片)。

## 分镜脚本：`videos/<短名>/storyboard.json`

```json
{"brief": {"for": "刚开始做饭的大学生", "gain": "知道为什么高原上煮面要更久", "line": "水开了不等于够热",
           "sec": 180, "lang": "zh", "voice": true, "must": [], "avoid": []},
 "ar": "16:9", "status": "草稿",
 "unify": {"pack": null, "palette": "从品牌色 #2F6FEB 推", "fonts": "…", "subs": "…", "trans": "…", "music": "…",
           "voice": {"model": "kokoro-v1.1-zh", "voice": "zf_083", "speed": 1.0}},
 "segments": [{"seg": "P1", "title": "冷开场", "content": "…", "sec": 15, "lead": "T", "typical": true,
               "uses": [{"what": "卫星图推近到发射场", "ref": "T-007", "materials": ["数据"]},
                        {"what": "大字砸进来", "ref": "C-036"},
                        {"what": "镜头光晕自己写", "class": "C"}],
               "shots": [{"what": "大全景：卫星图从太空推近到发射场", "ref": "T-007", "src": "assets/sat.jpg", "vo": [1, 2]},
                         {"what": "特写：「406,771 公里」砸进画面", "ref": "C-036", "vo": 3, "cut": "硬切"},
                         {"what": "中景：火箭立在塔架上，光晕扫过", "class": "C", "sec": 3, "cut": "溶解"}],
               "note": "…"}]}
```

顶层：

| 字段 | 写什么 |
|---|---|
| `plan` | 有策划时写：来自哪份 `plan.md`，相对项目根目录；逐字稿也写同一个。和 `brief` 只写一个 |
| `brief` | 无策划时写需求：`for` 给谁看、`gain` 看完得到什么、`line` 一句话主线、`sec` 目标秒数、`lang` 语言、`voice` 有没有旁白（`true`/`false`）、`must` 必须有（数组，可空）、`avoid` 不要（数组，可空）。和 `plan` 只写一个 |
| `ar` | 画幅，一版：`"16:9"`（默认）或 `"9:16"`，按用户需要；有策划时取自「篇幅与规格」。不出额外的短片 |
| `status` | `"草稿"` → `"用户确认"`（第 4 步用户点头后改）。用户确认前不做典型样片 |
| `unify` | 全片统一，见下面 |
| `segments` | 按播放顺序，每项是一段 |

全片统一 `unify`：每段的样式只管这段的画法和素材，颜色、字体、字幕、转场、声音都服从这一层。

| 字段 | 写什么 |
|---|---|
| `pack` | 用了风格包的写包名（`"news-brief"`），其余字段照包的 `STYLE.md`，可以不写；没用写 `null` |
| `palette` | 色板，或「从品牌色 #xxxxxx 推」 |
| `fonts` | 字体 |
| `subs` | 字幕样式和位置 |
| `trans` | 转场，全片 1–3 种 |
| `music` | 配乐的调子和音效 |
| `voice` | 旁白音色，对象 `{"model", "voice", "speed"}`：模型（适配命令认的名字）、音色名、语速（默认 1）；全片一个，配音工具读它。无旁白写 `null`。旧的一句话写法检查脚本只提醒 |

每段：

| 字段 | 写什么 |
|---|---|
| `seg` | 段号（`"P1"`）。有策划时对应框架的段号，怎么填见 [storyboard.md「seg 和 ref 怎么填」](storyboard.md#3-seg-和-ref-怎么填)；无策划时自己编 `P1`、`P2`…，按播放顺序，一段一个 |
| `title` | 这段的短标题 |
| `content` | 这段讲什么 |
| `sec` | 预计秒数，全片加起来贴近目标时长（无策划时是 `brief.sec`，有策划时是需求的目标时长） |
| `lead` | 本段主角类，`C`、`T`、`G` 之一：画面主要靠代码算（C）、真实素材（T）还是生成素材（G） |
| `typical` | 做典型样片的段写 `true`，全片 1–2 段，挑最难或最能代表全片的；别的段不写 |
| `uses` | 样式那一列：本段用到的风格、技术、素材，至少一条，可以好几条。每条 `what` 写做什么；库里有合适的风格写 `ref`（风格编号或 `pack:风格包名`，类别跟着风格走），没有的写 `class`（C/T/G），`ref`、`class` 只写一个；`materials` 写用到的素材类型（`data/tags.json` 的 `materials`，可选，T、G 类建议写）。`ref` 指的风格没有样片（只有「技术（建议）」）的，向用户说明没验证过。这里的 `ref` 指风格，和逐字稿里指事实的 `ref` 不是一回事 |
| `shots` | 可选，段里的分镜，按播放顺序，见下面[「分镜」](#分镜-shots) |
| `note` | 编排说明：分几层、谁驱动时间（旁白句子、音乐节拍还是匀速）、怎么接进前后段。第 2 步写打算，做完照实改，80–150 字 |

### 分镜 shots

一项是段里的一个画面，从这一刀到下一刀。分镜号不写进文件，按顺序数，写成「段序号-分镜序号」（`2-4`），和 `content.md` 的事实编号 `P2-4` 不是一回事。

| 字段 | 写什么 |
|---|---|
| `what` | 必填。画面：景别（大全景、全景、中景、近景、特写、微距）、主体、动作或运镜，一句话 |
| `ref` / `class` | 必填，只写一个，同 `uses`：库里有合适的风格写 `ref`，没有写 `class`（C/T/G）。生成的写清是生图还是生视频（写在 `what` 或 `src` 里） |
| `src` | 可选。用到的素材或参考图的路径（一个字符串或数组），生成的写首帧图、参考图；没有不写 |
| `vo` | 可选。对应本段第几句旁白，从 1 数（`2`，或 `[2, 3]`）；一句可以跨两个分镜（前一个写 `[2]`，后一个写 `[2, 3]`）。按旁白的顺序，没旁白不写 |
| `sec` | 可选。秒数，不少于 0.5。不写就随旁白定：切点落在它第一句旁白开始的时刻 |
| `cut` | 可选。从上一个分镜怎么接：`"硬切"`（默认）或 `"溶解"`；第一个分镜从上一段进来，走 `unify.trans`，不看它 |

秒数的规矩：

- 都写了 `sec` 的，同一段加起来等于段的 `sec`（差 0.05 秒以内）。
- 有的不写的，写了的加起来要小于段的 `sec`，余下的随旁白排。配过音以后段长照实际定，`tools/voice.py` 按真实的句子时刻排出每个分镜的起止，写进 `timing.json`（见「时间」）：写了 `sec` 的照它排；不写的切在它第一句旁白开始处（这句和上一个分镜共用时不算）；还定不下的切点，在前后定下的切点之间均分。都写了 `sec`、加起来和实际段长不一样的，最后一个分镜吃掉差额并提醒照实改。排出来不到 0.5 秒的分镜报错。
- 段代码用 `drawShots` 按分镜画、`shotAt` 查当前是第几个（[samples/API.md](samples/API.md)「完整出片的段」），不手写每个分镜的起点。

## 逐字稿：`videos/<短名>/script.json`

```json
{"plan": "plans/<短名>/plan.md",
 "segments": [{"seg": "P1", "vo": ["四十万零六千七百七十一公里。", "…"],
               "facts": [{"what": "离地球最远 252,756 英里（约 406,771 公里）", "ref": "P1-2",
                          "src": "https://…", "calc": "英里按 1.609344 换算成公里"}],
               "pace": {"lead": 1.2, "gap": 0.5, "min": 15}}],
 "heard": {"氢键": ["清箭"]}}
```

- `plan`：有策划时和分镜脚本写同一个；无策划时不写。
- `segments` 和分镜脚本的段按顺序一一对应，`seg` 照抄。
- `vo`：念的稿子，一句一项；数字按念法写（「四十万零六千七百七十一公里」）。没有旁白的片子写空数组。要字幕写法和念法不同，加顶层 `show`：`{"念法": "字幕写法"}`。
- `facts`：本段旁白和画面上的每个数字、事实各一条。`what` 写事实本身；`ref`、`src`、`calc`、`confirm` 怎么写见下面「事实的规矩」。
- `pace`（可选）：`lead` 第一句的声音从第几秒开始（默认 0.6），`gap` 句与句的有声部分之间留几秒（默认 0.3），`tail` 最后一句说完再留几秒（默认 0.8），`min` 本段最短几秒（默认 0）。
- `heard`（可选，顶层）：回听时识别器总听错的词，`{"稿子里的词": ["听成的", …]}`，只影响回听，见 [sound.md「完整出片的配音流程」](sound.md#完整出片的配音流程)。

## 时间：`videos/<短名>/timing.json`

配音工具 `tools/voice.py` 写，场景、`sound.py`、整片工具读；不手改。

```json
{"fps": 30, "voice": {"model": "kokoro-v1.1-zh", "voice": "zf_083", "speed": 1.0},
 "segments": [{"seg": "P1", "dur": 7.767,
               "vo": [{"file": "vo/P1_01.wav", "at": 0.74, "t": 2.455, "text": "四十万零六千七百七十一公里。", "show": "406,771 公里。",
                       "chars": [{"i": 0, "j": 1, "s": 0.8, "d": 0.21}]}],
               "shots": [{"t0": 0, "t1": 3.4, "cut": "硬切"}, {"t0": 3.4, "t1": 7.767, "cut": "溶解"}]}]}
```

- `dur`：段长（秒，整帧）。`vo` 每句：`file` 句子文件，`at` 在本段第几秒放（文件开头，含句首约 0.06 秒的留白），`t` 文件多长，`text` 念的稿子，`show` 字幕写法（`show` 换过的）。
- `shots`：分镜脚本这段写了 `shots` 才有，每个分镜在本段的起止和接法，排法见[「分镜」](#分镜-shots)。
- `chars`：逐字时间，`text[i:j]` 在本段第 `s` 秒起、念 `d` 秒；服务不返回逐字时间的（如本地 Kokoro）不写，字幕按句的起止出。
- 段代码里本段是 `SEG`，整个文件是 `TIMING`（跨段连续的东西，如整片时钟、进度条，用它算本段在整片里的起点）。读了 `TIMING` 的段，别的段的段长变了也会重渲。

## 事实的规矩

- 旁白和画面上的每个数字、事实都要在 `facts` 里有一条，有出处：
  - 有策划：`ref` 写 `content.md` 里那一条的编号（见 [storyboard.md](storyboard.md#3-seg-和-ref-怎么填)），设定、虚构的写 `null`；`src` 写这条的来源链接；换算、推算的 `src` 写 `null`，加 `calc` 写算法和用到的编号。
  - 无策划：`ref` 写 `null`；`src` 写链接，或「用户提供」「设定」；换算、推算的加 `calc`。助手自己补的事实加 `"confirm": "待用户确认"`，用户确认后改成 `"用户确认"`，用户不要的删掉、旁白跟着改。
- 不新造用户没确认过的数字；拿不准的不讲，也不自己挑一个数讲。
- 照写口径：时区、单位、版本、统计范围。某方自己说的、计划中的，讲成「官方称」「按计划」，不讲成事实。
- 有策划时另有几条（只引用「已核实」的、照「必须写清的」等），见 [storyboard.md「事实」](storyboard.md#4-事实)。

## 检查

只用标准库，退出码 0 没有问题（可能有提醒），1 有问题要改，2 读不了。查的就是上面几节的规矩：分镜脚本和逐字稿对得上、每段至少一条 `uses`、`ref` 在 `data/styles.json` 或 `packs/` 里、分镜的字段和秒数（`vo` 是这段有的句子、按顺序，`sec` 合计等于段的 `sec`）、`unify` 齐、`plan` 和 `brief` 只有一个、秒数贴近目标、事实都有出处。

```bash
# 无策划；不写 --script 时用分镜脚本同目录的 script.json
python3 <本 Skill 目录>/scripts/check_storyboard.py videos/<短名>/storyboard.json --table
# 有策划：另查段号和事实编号，通用的部分它调 check_storyboard.py
python3 <本 Skill 目录>/scripts/check_plan.py plans/<短名>/plan.md \
    --storyboard videos/<短名>/storyboard.json --script videos/<短名>/script.json --table
```

- `--table`：打印段落表、每段的分镜表、全片统一和「待用户确认」的事实，第 4 步照它给用户看。没写 `sec` 的分镜显示「随旁白」；分镜脚本同目录有 `timing.json`（配过音）时，按它显示每个分镜的实际起止。
- `--ready`：第 5 步做典型样片前加上，再查 `status` 是「用户确认」、事实里没有「待用户确认」、标了 `typical`。
