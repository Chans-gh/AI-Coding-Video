# 完整出片：从内容到整片

用户要「做一支 X 分钟的片子」时读这份。只要看看效果、挑风格、定一套风格的，走风格演示（`SKILL.md`「两条线」）。

产物都放用户项目的 `videos/<短名>/`：`storyboard.json`（分镜）、`script.json`（逐字稿），之后是典型样片和整片。有策划时也不写进 `plans/`。

## 六步

每一步都要用户点头才往下；停在哪一步都行。

1. **定内容**：有策划（项目里有 `plans/<短名>/plan.md`，交接格式 2、状态「已交接」）的照 [storyboard.md](storyboard.md) 接，要讲什么不改，缺内容回流给策划。没有策划的，整理用户给的内容，或从用户的主题和要求往外扩展；内容多、要查证的，建议用户先用 [ai-content-planner](https://github.com/Chans-gh/AI-content-planner)。
2. **拆分镜与样式**：分段、每段讲什么、每段用什么样式（一个或几个风格编号或风格包，加技术路线和素材类型），同时定全片统一（色板、字体、字幕、转场、配乐、旁白音色）。查风格照 `SKILL.md`「怎么查」。写进 `storyboard.json`，格式见下面「分镜」。
3. **逐字稿**：每段念什么、画面上出现的每个数字和事实从哪来。写进 `script.json`，格式和规矩见下面「逐字稿」「事实的规矩」。
4. **用户确认**：分镜和逐字稿一起给用户看，用户点头才往下。
5. **典型样片（含配音）**：先挑 1–2 段最难或最能代表全片的，用整片的画幅做出来，带旁白和配乐，给用户看；不满意回到第 2 步改样式，不直接改代码凑。旁白和配乐照 `sound.md`，素材照 `materials.md`。
6. **渲染整片**：分段渲染、单独检查，再接成整片、统一混音。出片和自检照 `making.md`。

## 分镜：`videos/<短名>/storyboard.json`

```json
{"plan": "plans/<短名>/plan.md", "style": "C-036", "ar": "9:16",
 "segments": [{"seg": "P1", "title": "冷开场", "content": "…", "sec": 15, "lead": "C",
               "uses": [{"what": "大字砸进来", "ref": "C-036"}, {"what": "发射录像慢放", "class": "T"}],
               "note": "…"}]}
```

| 字段 | 写什么 |
|---|---|
| `plan` | 有策划时必填：来自哪份 `plan.md`，相对项目根目录；逐字稿也写同一个 |
| `style`、`ar` | 选定的风格编号（或 `pack:风格包名`）、画幅（有策划时取自「篇幅与规格」） |
| `segments` | 按播放顺序，每项是一段分镜 |
| `seg` | 段号（`"P1"`）。有策划时对应框架的段号，怎么填见 [storyboard.md「seg 和 ref 怎么填」](storyboard.md#3-seg-和-ref-怎么填) |
| `title` | 这段分镜的短标题 |
| `content` | 这段讲什么 |
| `sec` | 预计秒数，全片加起来贴近目标时长 |
| `lead` | 本段主角类，`C`、`T`、`G` 之一：画面主要靠代码算（C）、真实素材（T）还是生成素材（G） |
| `uses` | 用到的技术，每条 `what` 写做什么；有对应样片的写 `ref`（样片编号或 `pack:风格包名`，类别跟着样片走），没有的写 `class`（C/T/G）。`ref`、`class` 只写一个。这里的 `ref` 指样片，和逐字稿里指事实的 `ref` 不是一回事 |
| `note` | 编排说明：分几层、谁驱动时间（旁白句子、音乐节拍还是匀速）、怎么接进前后段。分镜时写打算，做完照实改，80–150 字 |

## 逐字稿：`videos/<短名>/script.json`

```json
{"plan": "plans/<短名>/plan.md",
 "segments": [{"seg": "P1", "vo": ["四十万零六千七百七十一公里。", "…"],
               "facts": [{"what": "离地球最远 252,756 英里（约 406,771 公里）", "ref": "P1-2",
                          "src": "https://…", "calc": "英里按 1.609344 换算成公里"}],
               "pace": {"lead": 1.2, "gap": 0.5, "min": 15}}]}
```

- `segments` 和 `storyboard.json` 的段按顺序一一对应，`seg` 照抄。
- `vo`：念的稿子，一句一项；数字按念法写（「四十万零六千七百七十一公里」）。没有旁白的片子写空数组。要字幕写法和念法不同，加顶层 `show`：`{"念法": "字幕写法"}`。
- `facts`：本段旁白和画面上的每个数字、事实各一条。`what` 写事实本身；`ref` 写事实的编号（有策划时是 `content.md` 里那一条，见 [storyboard.md](storyboard.md#3-seg-和-ref-怎么填)），设定、虚构的写 `null`；`src` 写这条的来源链接；换算、推算的 `src` 写 `null`，加 `calc` 写算法和用到的编号。
- `pace`（可选）：`lead` 旁白前留几秒，`gap` 句与句之间另留几秒给画面，`tail` 旁白后留几秒，`min` 本段最短几秒。

## 事实的规矩

- 旁白和画面上的每个数字、事实都要在 `facts` 里有一条，有出处（`src`）、算法（`calc`）或标明是设定（`ref` 写 `null`）。
- 不新造用户没确认过的数字；拿不准的不讲，也不自己挑一个数讲。
- 照写口径：时区、单位、版本、统计范围。某方自己说的、计划中的，讲成「官方称」「按计划」，不讲成事实。
- 有策划时另有几条（只引用「已核实」的、照「必须写清的」等），见 [storyboard.md「事实」](storyboard.md#4-事实)。
